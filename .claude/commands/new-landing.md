Создай новую ветку лендинга: `$ARGUMENTS`

Порядок строгий, не пропускай шаги.

## 1. Память и занятые интенты

```bash
cat docs/memory/landings-registry.md
node tooling/check-uniqueness.mjs
```

Если предложенный интент дублирует уже живой домен — скажи об этом
и предложи другой угол, а не создавай дверную страницу.

## 2. Бриф

Заполнять коммерческие поля без брифа нельзя. Спроси у человека:

- домен и точный поисковый интент
- аудитория: кто именно, каким укладом живёт
- какие форматы реально есть в этом фокусе
- канал контакта (`cta.primaryChannel` / `primaryValue`)
- бренд в шапке
- 2–5 соседних доменов для перелинковки
- для `type: project` — застройщик, этап, инвентарь

Чего человек не дал — остаётся `[ДАННЫЕ]`. **Не придумывай**: цены,
yield, сроки, юридические нормы, отзывы, «осталось N».

## 3. Скрипт

```bash
npm run new:landing -- --slug <slug> --type <type>
```

Скрипт создаёт каталог из `_example`, ветку `landings/<slug>` и черновик
конфига с пустыми коммерческими полями. Он ничего не деплоит.

## 4. Заполнение

Используй навыки: `fonar-writing`, `seo-copy`, `quiz-preset`, `explain-writing`.
Соблюдай `organic-guardrails`.

Минимум: Фонарь (12–22 слова, уникален), H1 без бренда, 4+ FAQ,
3+ разъяснения, 2–5 соседей с анкорами по интенту.

## 5. Проверка

```bash
node tooling/validate-landing.mjs --slug <slug>
npm run build:landing -- --slug <slug>
```

## 6. Реестр

Допиши строку в `docs/memory/landings-registry.md` со статусом `черновик`.

## Формат ответа

Без преамбулы «конечно, вот лендинг». Отдай:

1. slug, type, предлагаемый domain-pattern
2. title, description, H1
3. текст Фонаря
4. пресет квиза и маршруты
5. `config.json`
6. контентные файлы
7. список `[ДАННЫЕ]` — что осталось запросить у человека
8. 3 соседних домена для перелинковки

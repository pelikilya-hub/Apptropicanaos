# Память проекта

Память живёт в git, а не в голове сессии. Два файла:

| Файл | Что там |
|---|---|
| `docs/memory/decisions.md` | архитектурные решения и почему именно так |
| `docs/memory/landings-registry.md` | реестр: slug, type, домен, интент, удар разбора, статус |

## В начале работы над веткой

```bash
cat docs/memory/landings-registry.md
node tooling/check-uniqueness.mjs
```

Это отвечает на «какие интенты уже заняты» и «свободен ли этот угол разбора»
быстрее, чем чтение всех конфигов.

## Когда обновлять реестр

- создали ветку → строка со статусом `черновик`
- заполнили конфиг → вписали удар разбора и интент
- подключили домен → статус `живой`, домен проставлен
- закрыли домен → статус `архив`, строку **не удалять**

Строка не удаляется никогда: удалённый домен всё равно занимает интент
в глазах поиска ещё долго.

## Когда писать в decisions.md

Решение попадает в файл, если оно:

- меняет каркас или контракт конфига
- отменяет прежнее решение
- объясняет неочевидный запрет

Формат: дата · решение · причина · что стало невозможно.
Не журнал коммитов — только развилки.

## Память между сессиями

Плагин `episodic-memory` ищет по прошлым разговорам Claude Code
(навык `remembering-conversations`). Это дополняет, но **не заменяет**
файлы выше: договорённости, которые должны пережить смену машины
и попасть к коллеге, живут в git.

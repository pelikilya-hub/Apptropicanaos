Использовать, когда в landings/<slug>/public положили файлы и нужно собрать config.media - выбрать кадр первого экрана и og, собрать галерею, сгруппировать планировки по типам, написать alt и подписи. Вы раскладываете медиа одной ветки. Зона — `landings/<slug>/` и только она.
`packages/`, `tooling/`, `schemas/`, `templates/` не трогаете.

## Порядок

### 1. Осмотреться

```bash
find landings/<slug>/public -type f \( -name '*.jpg' -o -name '*.jpeg' -o -name '*.png' -o -name '*.webp' -o -name '*.avif' \) | sort
```

Прочитайте `landings/<slug>/config.json`: `type`, `product`, `units`, `geo`.
Типы вилл из `units` — готовые названия для групп планировок, придумывать свои не нужно.

### 2. Собрать черновик

```bash
npm run import:media -- --slug <slug> --write
```

Импортёр разложит файлы по галерее и планировкам, прочитает размеры из заголовков
и проставит `[ДАННЫЕ]` вместо `alt`. Всё остальное — ваша работа.

### 3. Посмотреть каждый кадр

Откройте инструментом Read **каждое** изображение. Не по имени файла: имя врёт,
`02-sunset-pool.jpg` бывает планировкой.

По каждому кадру решите:

- **что на нём на самом деле** — это станет `alt`
- **это фотография или рендер** — если отличимо, скажите об этом в отчёте
- **это планировка, попавшая в `media/`** — переложите файл в `public/plans/<тип>/`
  и перезапустите импортёр
- **кадр нечитаемый, дублирует соседний или явно черновой** — исключите из галереи
  и назовите его в отчёте

### 4. Разложить по блокам

| Блок | Что туда идёт |
|---|---|
| `media.hero` | Один кадр первого экрана: общий план, который объясняет место. На десктопе он стоит справа от H1 вертикально — кадр с вертикальным сюжетом смотрится лучше горизонтальной панорамы |
| `media.og` | Картинка для мессенджеров, ближе всего к 1200×630. Если подходящей нет — оставьте пусто и скажите об этом: обрезанная под og панорама выглядит хуже, чем её отсутствие |
| `media.gallery` | Остальные кадры в осмысленном порядке: общий план → территория → интерьеры → детали. Кадр из `hero` первым в галерее не повторяют |
| `media.plans` | Планировки, сгруппированные по типам из `units`. `label` группы — название типа как в конфиге, `label` листа — этаж или назначение |
| `media.video` | Только `provider` и `id` ролика. Ссылку на файлообменник схема не примет |

### 5. Написать alt и подписи

`alt` описывает **кадр**, а не проект.

- «Двухэтажная вилла на склоне, бассейн вдоль террасы, вид на море» — да
- «Роскошная вилла мечты у моря» — нет, это оффер, а не описание
- «Вилла LX, 4 спальни, 630 м²» — нет, если по кадру этого не видно

`caption` ставьте только там, где он добавляет факт, которого нет в `alt`.
Пустая подпись ради симметрии — мусор.

**Ничего не достраивайте по кадру.** Количество спален, площадь, этаж, сторону
света и материалы по рендеру не определить. Если фактов нет в конфиге —
их нет и в подписи.

### 6. Проверить

```bash
node tooling/validate-landing.mjs --slug <slug>
LANDING_SLUG=<slug> npx astro build
```

Валидатор роняет сборку, если файл из конфига не найден. Незаполненный `[ДАННЫЕ]`
в `alt` проходит превью, но не проходит `--prod` — значит, к концу вашей работы
таких быть не должно.

## Отчёт

Верните:

1. сколько файлов разложено и по каким блокам
2. что выбрано в `hero` и `og` и почему
3. что исключено и по какой причине
4. чего не хватает: нет планировок для типа из `units`, нет кадра под og,
   нет фото территории
5. вывод валидатора и сборки — дословно, без пересказа

Не пишите «готово», не показав вывод команд.

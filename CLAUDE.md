# Фабрика лендингов — рабочая инструкция

`PROMPT.md` — конституция репозитория. При расхождении побеждает он.
Этот файл описывает, как здесь работать руками.

## Что это

Монорепозиторий лендингов недвижимости Пхукета.
`main` — каркас, дизайн-система, движок квиза, схемы, CI.
Каждая посадочная живёт **в отдельной ветке** и выкатывается **на свой домен**.

**Одна ветка = один домен = один поисковый интент.**

## Железные правила

- В каркас не зашивается имя комплекса, район, цена, застройщик, телефон, оффер.
  Всё уникальное приходит из `landings/<slug>/config.json`.
- **Фонарь — офферный блок** (цена, условия, срок, остаток), необязательный.
  **«Стоит понять до просмотра»** — честный разбор, обязателен всегда.
  Первый конвертит, второй кормит органику.
- Факта нет в конфиге — пишем `[ДАННЫЕ]`. Цифры рынка, yield, юридические схемы
  и отзывы не выдумываем никогда.
- Срок и остаток живут только полями `fonar.deadline` и `fonar.scarcity`,
  каждое с `source` и `validUntil`. В свободном тексте «осталось N» и
  «успей купить» роняют сборку. Прошедшая дата тоже.
- Обратно в `main` из ветки лендинга едет только общее: баг компонента, токен,
  улучшение движка квиза. Контент комплекса в `main` не тащить.
- Секреты аналитики в git не попадают. В конфиге — только имя провайдера.

## Стек

Astro (статический вывод) + Tailwind поверх токенов `packages/ui`.
Без jQuery, без тяжёлого SPA, без общей CMS на все домены.
`dist/` обязан открываться как набор статических файлов.

Mobile-first, базовый холст 390–430px, **428px без горизонтального скролла**.

## Команды

```bash
npm run new:landing -- --slug <slug> --type <type>   # ветка + каркас конфига
npm run validate:landing                             # гейт перед сборкой
npm run validate:landing -- --prod                   # требования боевого домена
npm run build                                        # валидация + astro build
npm run build:landing -- --slug <slug> [--prod]      # сборка одной ветки с отчётом
npm run audit:uniqueness                             # пересечения между доменами
npm run dev                                          # локальный просмотр
```

Активный лендинг выбирается автоматически: единственный каталог в `landings/`
этой ветки. Явно — через `LANDING_SLUG`.

## Карта репозитория

```
packages/ui        токены, сетка, кнопки, шапка/подвал, липкий CTA
packages/fonar     Фонарь — офферный блок: цена, условия, срок, остаток
packages/insight   «Стоит понять до просмотра» — честный разбор
packages/quiz      движок квиза, пресеты, маршруты
packages/explain   аккордеон разъяснений
packages/seo       мета, canonical, og, schema
packages/analytics адаптер событий, без ключей
packages/legal     дисклеймер
packages/config    чтение конфига ветки, [ДАННЫЕ]
templates/landing  скелет страницы, фиксированный порядок секций
schemas/           валидация конфига и пресета квиза
tooling/           create / validate / build / uniqueness / forbidden
landings/_example  шаблон ветки
docs/memory/       реестр доменов и принятые решения
```

## Порядок работы над веткой

1. `docs/memory/landings-registry.md` — какие интенты уже заняты
2. бриф от человека; чего нет — остаётся `[ДАННЫЕ]`
3. `npm run new:landing`
4. заполнение конфига (навыки `insight-writing`, `fonar-writing`, `seo-copy`,
   `quiz-preset`, `explain-writing`)
5. `node tooling/validate-landing.mjs`
6. приёмка по навыку `landing-acceptance`
7. строка в реестр

## Навыки этого репозитория

`fonar-writing` (оффер) · `insight-writing` (разбор) · `quiz-preset` ·
`explain-writing` · `seo-copy` · `organic-guardrails` · `landing-acceptance` ·
`design-system` · `landing-memory`

Команды: `/new-landing` · `/check-landing` · `/landing-matrix`
Агент: `landing-editor` — контент одной ветки, без правок каркаса.

## Просят «сделать сразу 50 доменов»

Отказать в генерации тонких копий. Вернуть матрицу слотов **type × geo × audience**
и создавать ветки пачками по 3–5 с уникальными Фонарями. См. `/landing-matrix`.

## Не заявлять о готовности без проверки

Прежде чем сказать «готово», запустите валидатор и сборку и покажите вывод.
Пункт приёмки, который не проверен, не отмечается.
